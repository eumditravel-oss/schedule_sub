# D1 마이그레이션 정책

## 기본 규칙

1. QA 또는 운영에 한 번이라도 적용된 SQL 파일은 이름과 내용을 바꾸지 않습니다.
2. 스키마 변경은 항상 새 파일로 추가합니다.
3. 새 번호는 현재 최댓값보다 큰 네 자리 번호를 사용합니다. 다음 번호는 `0026`입니다.
4. QA에서 스키마 사전 점검과 애플리케이션 회귀 테스트를 통과하기 전에는 운영에 적용하지 않습니다.
5. 삭제·재구축처럼 복구가 어려운 변경은 사전 백업과 명시적인 운영 승인이 필요합니다.

## 중복된 0015 파일

저장소에는 다음 두 파일이 이미 존재합니다.

- `0015_add_schedule_revision_to_tasks.sql`
- `0015_task_groups_hierarchy.sql`

번호는 중복이지만 파일명은 서로 다르고 기존 환경에 적용됐을 수 있으므로 이름을 바꾸지 않습니다. Wrangler/D1이 파일명을 마이그레이션 식별자로 기록하므로, 과거 파일을 정리하려고 이름을 변경하면 이미 적용된 환경에서 새 마이그레이션으로 오인될 수 있습니다.

이후에는 번호를 중복하지 않으며 `0026_<설명>.sql`부터 순차적으로 추가합니다.
